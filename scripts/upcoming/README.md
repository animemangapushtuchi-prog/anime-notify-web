# 来期（2027年冬）の放送日・配信先の更新

公式サイトに書いてあることだけを根拠に、`content/upcoming/2027-winter.json`（放送予定）と配信の行を作る道具です。
1月中旬まで週2回くり返す想定です。

## 手順

```
node scripts/upcoming/scan.mjs      # 1. 公式サイトを読む（5分ほど）。作品ごとの「放送・配信」の行が出る
node scripts/upcoming/diff.mjs      #    前回確かめたときから本文が変わった作品だけを出す（2回目以降はこれを読めば足りる）
                                    # 2. 出力を読んで 2027-winter.evidence.json（台帳）を直す
node scripts/upcoming/build.mjs     # 3. 根拠を機械で確かめて書き出す
```

- scan に作品IDを付けると、その作品だけ読み直す（例 `node scripts/upcoming/scan.mjs 214049`）
- 読んだ本文は一時フォルダ（Windows なら `%TEMP%\animiru-upcoming\2027-winter\`）に保存される。リポジトリには入らない
- scan の出力の印
  - 【新】台帳に無い作品 → 読んで、放送予定（schedule）に足すか、足せない理由を skip に書く
  - 【消】台帳の根拠の文が公式ページから消えた → 日付が決まった・文が変わった可能性。ページを見て直す
  - 「台帳 ○／×」は根拠が本文にあるか、「候補」は自動で読み取った配信サービス（そのまま使わない。下のルールで判断）
- build は根拠の文（evidence）が本文に1つでも無いと、何も書かずに止まり、どの行かを表示する
- 書き出し先
  - `content/upcoming/2027-winter.json` … サイトの放送予定一覧に使われる（push すると反映）
  - `scripts/upcoming/out/2027-winter.rows.json` … 配信の行。Firestore にはまだ入れない（git にも入らない）

## 台帳（2027-winter.evidence.json）の書き方

- `schedule`：放送・上映の予定。`start` は "2027-01-10"（日付まで発表）か "2027-01"（月だけ）。`kind` は "tv" か "movie"。`slot`・`tv` は未発表なら ""
- `streaming`：配信。`serviceKey` は lib/streaming.ts のキー（d-anime, abema, netflix, prime-video, u-next など）。
  `weeklyDay` は 0=日〜6=土。深夜は放送の慣習どおり（「土曜26:30」→ 6 と "26:30"）
- `skip`：入れなかった作品と理由（公式サイトなし・403・本文が取れない・時期の記載なし など）
- `evidence`：公式ページの本文からそのまま写した短い文（1文まで）。空白の違いは無視して照合する
- 公式サイトのトップ以外のページを読ませたいときは、その行に `"url": "https://…"` を足すと scan が一緒に読む

## 判断ルール

- **推測で書かない。** 公式ページの本文に書かれていることだけ
- **続編の公式サイトに並んでいる配信サービスは、ほとんど前のシーズンの案内**（「第1期配信中」「好評配信中」）。
  この冬の作品の配信として書くのは、その期の配信だと本文から分かるものだけ。迷ったら入れない
- 「独占先行配信」「最速配信」は最速（isFastest）。独占（isExclusive）は「独占配信」「見放題独占」と書いてあるときだけ
- 1行に複数のサービスが並び、日付が1つだけのときは、日付をどのサービスにも付けない
- サイトが 401/403/429 を返したら読まない（名乗りを偽らない）。JavaScript で描くサイトで本文が取れないものも無理に取らない。どちらも skip に理由を書く
- 公式の文章を長く写さない（evidence は1文まで）
- AniList の冬の作品でも、公式が「2026年12月開始」などと書いていれば冬の一覧には入れない（skip に理由）
